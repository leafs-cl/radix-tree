# 2. 前缀缓存基数树（raidix-prefix-cache）

- 核心：压缩前缀树的匹配和分裂 + LRU驱逐
- 背景：System Prompt和历史重算prefill很浪费，把已缓存的token序列组织成基数树，新请求进来先找最长前缀
- 难点：节点分裂，即多条序列共享前K个token时，原来那个节点必须从中间劈开，而且LRU的时间戳要跟着一起劈对

## 规格契约
- 树的每一条边带一段token序列（不是单个token），即压缩
- insert的时候把一条token序列写进树，与已有分支共享的部分不重复存
- match prefix返回这条序列在树种能匹配上的最长前缀长度
- 插入时若某个节点只匹配了一部分，必须把该节点分裂成两个
- evict按lru驱逐叶子节点，直到释放了num_tokens个token
- 只有叶子可以驱逐-否则可能会让孩子节点失去前缀
- 需要有全局时钟：每次insert或者match prefix让它加一，时间戳因此互不相同。没有平局的驱逐顺序才是确定的，对拍才有意义

## 核心问题
- 删除和插入的效率

## 验收标准
- total tokens等于把树上所有边的长度加起来
- 任何节点的子节点，其边的首个token两两不同
- insert之后立刻match prefix同一条序列，必然返回完整长度
- evict只删叶子，删完之后剩下的每条路径仍是某条曾插入序列的前缀
